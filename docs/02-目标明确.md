# 目标明确：把"做完"写成能判真假的断言

## 为什么"做一个好用的 TODO App"不算目标

它没法检查。AI 做到哪一步都可以说"做完了"，你也没法反驳。pstack 在好几个地方堵这个口子：

- [figure-it-out](../.claude/skills/figure-it-out/SKILL.md) 的 Phase A：开跑之前，必须能说出"完成的定义，写成一个可证伪的断言"。
- [pstack 指南第 7 章](https://github.com/backnotprop/pstack/blob/main/docs/guide/07-overnight.md) 的提醒："时长不是完成条件。'在这上面干 4 小时'什么都检查不了。"
- [prove-it-works](../.claude/skills/principle-prove-it-works/SKILL.md)：在真实的东西上验证，不看代理指标，不信自我汇报，"编译通过"也不算。

## 这次的 7 条完成断言

澄清阶段的结论，直接变成了下面这些断言。每一条都有字面上确定的期望值，要么通过，要么失败：

| # | 断言 | 行为测试 | 真浏览器 |
|---|---|---|---|
| P1 | 爱奇艺 25/月、网易云 148/年、iCloud 21/月、腾讯视频 30/月，首页显示每月 **¥88.33** | ✓ | ✓ |
| P2 | 1/31 开通的月付订阅 2 月扣费日是 **2/28**，3 月回到 **3/31**；7 天内的扣费出现在日程里，10/3 的不出现 | ✓ | ✓ 日程部分 |
| P3 | 周期水果点"买了"后离开日程，满周期后**自动回来**；一次性的买了就不再出现 | ✓ | ✓ 周期部分 |
| P4 | "下次分享"卡片显示今天及以后**最近的一场**，过期的不算 | ✓ | ✓ |
| P5 | **刷新页面后数据还在** |  | ✓ |
| P6 | 北京时间早上 7 点（这时 UTC 还是前一天），"今天"按**本地日期**算 | ✓ | ✓ |
| P7 | "我去买"把 7 天内要买的东西**复制成一条消息**；手机没有剪贴板时显示文字让人手动复制 | ✓ | ✓ |

P7 是纠偏之后加的，见 [docs/04](04-路径纠正.md)。

P6 值得单独说一句。代码里最常见的"今天"写法是 `new Date().toISOString().slice(0, 10)`。它取的是 UTC 日期，在中国每天 0 点到 8 点会算成昨天。这个 bug 只在你们家的时区、只在早上才出现，平时测不出来。所以端到端测试专门把浏览器设成北京时区、把时钟拨到早上 7 点。

## 只有一个裁判

所有断言由一个命令判定（[`scripts/verify.sh`](../scripts/verify.sh)）：

```bash
npm run verify
```

它依次跑三步，全部通过才打印 `VERIFIED`：

1. **行为测试**（[`test/domain.test.js`](../test/domain.test.js)）。像真正的调用者一样调用代码，拿结果和字面期望值比较。
2. **变异检查**（[`scripts/mutation-check.mjs`](../scripts/mutation-check.mjs)）。往代码里植入 8 个已知 bug，每一个都必须让至少一条测试变红。它证明的是"测试本身是有效的"。
3. **真浏览器端到端**（[`test-e2e/run.mjs`](../test-e2e/run.mjs)）。启动真实页面，像人一样点按钮、填表单。

第 2 步是这次路上加的。原因是我发现一条单元测试**碰巧通过**了，详见 [docs/04](04-路径纠正.md) 的"纠正 2"。

## 为什么要三层

| 层 | 它能抓到的 | 它抓不到的（这次真实遇到过） |
|---|---|---|
| 行为测试 | 日期计算、金额折算、窗口边界 | 服务器把首页当二进制文件发出去 |
| 变异检查 | 测试写得太松、碰巧通过 | 界面问题 |
| 真浏览器 | 整条链路：服务器、页面、存储、剪贴板 | （最慢，所以不拿它测每个日期边界） |

[test-behavior-not-implementation](../.claude/skills/principle-test-behavior-not-implementation/SKILL.md) 原则给了一个自检方法："如果把每个被导入的函数都换成返回 `undefined`，这条测试还能通过吗？能的话，就改断言或者删掉测试。"变异检查是把这个自检变成了脚本。

## 你可以这样说

```text
/poteto-mode 新任务。<目标>。
完成条件：<一条命令> 输出 <某个确定的结果>，并且在真实页面上能看到 <具体现象>。
先把完成条件写成测试和一个 verify 脚本，再开始实现。
```

离开电脑、让它自己跑的时候（pstack 称为 overnight contract）：

```text
/poteto-mode 我要离开一会儿。<目标>，在新的 worktree 里做。
完成的意思是 npm run verify 输出 VERIFIED。
记决策日志。提交前不用问我。
如果卡住超过一小时，停下来写清楚为什么。
```
