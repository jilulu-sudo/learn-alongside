# 提示词速查和练习

在 Claude Code 里打开本仓库，pstack 已经装好。下面的提示词可以直接复制，把尖括号里的内容换成你自己的。

## 第一次使用

```text
/setup-pstack
```

pstack 默认配置的是 Cursor 里的模型，Claude Code 里没有。跑一次这个命令，把各个角色都选成 `inherit-parent`（沿用当前对话的模型）。

## 四种能力各用什么提示词

**需求澄清**

```text
/poteto-mode 新任务。我想做 <一句话需求>。先别写正式代码。
把需求拆成问题。能靠跑原型或脚本看到答案的，直接做出来测；
只有产品方向和个人偏好才问我，而且每个问题先给默认选项。
```

```text
/poteto-mode 做两三个原型比较一下 <要决定的事>，放在一个页面里用按钮切换。
先定一个能量化的比较标准，再截图给我看。
```

**目标明确**

```text
/poteto-mode <目标>。完成条件：<命令> 输出 <确定的结果>，
并且在真实页面上能看到 <具体现象>。先把完成条件写成测试和 verify 脚本，再实现。
```

**路线规划**

```text
/architect with checkpoint. 先写调用方怎么用，再给类型和模块划分，停下来给我看。
```

```text
/poteto-mode 这是多阶段的工作：<描述>。先出计划，不要实现。
```

**路径纠正**（一句话，说原则的名字）

```text
apply prove it works. 给我看真实输出，不要看构建日志。
attack the premise. 先把你前两次修复共同的前提写出来。
i said the goal is to repro. i did not ask for a fix yet.
```

**让它自己跑，回来再审**

```text
/poteto-mode 我要离开一会儿。<目标>。完成的意思是 npm run verify 输出 VERIFIED。
记决策日志。提交前不用问我。卡住超过一小时就停下来写清楚为什么。
```

```text
/show-me-your-work 我回来了，把你做了什么整理给我看
```

**听不懂它在说什么**

```text
/bro
```

## 常见错误

这些来自 pstack 指南第 10 章：

- **在提示词里罗列技能**，比如"先用 /how 再用 /architect"。执行手册已经排好顺序了，你排的通常会漏步骤。只说目标和约束。
- **完成条件太模糊**。"做得更好"、"干 4 小时"都检查不了。
- **多个 AI 在同一个工作目录里干活**。它们会互相覆盖。说"每个尝试用自己的 worktree"。
- **看到构建通过就当成功**。构建只证明能编译。要求它给出真实的运行结果。

## 练习：在这个 App 上继续做

从易到难排列。每个练习都写了预期会走哪本执行手册，你可以对照它实际选的是不是这本。

**练习 1：弄懂现有代码**（Investigation）

```text
/how 这个 app 的"接下来 7 天"日程是怎么算出来的？为什么下次扣费日不存起来？
```

看它的回答有没有引用具体文件和行号，有没有说到 `KINDS` 表。

**练习 2：续费前提醒**（Feature）

```text
/poteto-mode 订阅在扣费前 3 天，首页要有醒目提示，方便我决定要不要取消。
```

观察它有没有先找数据形状（要不要在 `KINDS` 里加东西），有没有写完成断言，有没有跑 `npm run verify`。

**练习 3：学习分享轮流主讲**（Feature，会触发 architect）

```text
/poteto-mode 学习分享要轮流主讲。家里有爸爸、妈妈、小宇三个人，
每办完一场，下一场自动排给下一个人。
```

这个需求会碰到"一场活动"和"一个轮换序列"两种数据。观察它是在 `activity` 上打补丁，还是按 redesign-from-first-principles 重新想数据形状。

**练习 4：修一个真 bug**（Bug fix）

页面开着过了午夜，日期不会自动更新（见 docs/04 的 Attention 部分）。

```text
/poteto-mode 页面开着过了午夜，"今天"不会更新，要重新打开才对。repro first, then fix and verify.
```

观察它有没有**先复现**，比如用 Playwright 的时钟 API 快进到午夜，再动代码。

**练习 5：全家同步**（figure-it-out）

```text
/poteto-mode 我想让全家的手机看同一份数据。
先把可选方案和各自的成本列出来，产品层面的选择问我，然后设计这次改造。
我会事后审查，记决策日志。
```

这是 docs/04 留给你的决定。观察它能不能分清"要问你的"和"可以直接做的"。

**练习 6：审查这次演示**（interrogate）

```text
/interrogate 审查整个仓库，要严格。先不要改任何东西。
只报真正的 bug 或行为退化，不要吹毛求疵。
```

看它能不能找出我自己没发现的问题。它找到的，就是这次演示跳过多模型审查的代价。
