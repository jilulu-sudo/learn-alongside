# 意象词典

这部课只有一个意象：一根线。下面逐条写清楚，画面里的每一样东西对应 Effect v4 的哪个概念、哪一行代码，以及它是怎么被真实运行证实的。

## 基本笔画

| 画面 | 意思 | 对应 |
|---|---|---|
| 一根实线 | 一个程序 | 一个 `Effect<A, E, R>` 值 |
| 虚线 | 还没运行的程序，像一张没开工的图纸 | Effect 是惰性的描述 |
| 沿线走的珠子 | 一次运行 | `Effect.runSync` / `runPromise` |
| 线的终点，青色的点 | 成功的值 | 类型参数 A |
| 线下面的朱色岔路 | 预期内的失败，带名字 | 类型参数 E，`Data.TaggedError` |
| 线上的缺口（靛色虚线框） | 运行前需要的服务 | 类型参数 R，`Context.Service` |
| 填进缺口的料 | 服务的实现 | `Layer` |
| 从岔路接回主线的桥 | 处理掉一种错误 | `Effect.catchTag`、`Effect.catch` |
| 一道没有画在图纸上的裂缝 | 程序的 bug | defect，`Effect.die` |
| 时间轴上的粗段 | 一次请求正在跑 | 在测试时钟上记录的起止时刻 |
| 两段之间的弧线 | 等待 | `Schedule` 给出的间隔 |
| 竖直的红色虚线 | 时限 | `Effect.timeout` |
| 平行的几根线 | 同时在跑的纤程 | `Fiber`，`Effect.all({ concurrency })` |
| 线头上的一道斜杠 | 被中断 | interrupt |
| `[` 和 `]` | 拿到资源、还掉资源 | `Effect.acquireRelease` |
| 一摞盘子 | Scope 里登记的收尾动作 | 后放上去的先拿下来 |
| 印章 | 章节 | 序、一……七、终 |
| 底部的 `Effect<A, E, R>` | 这一刻程序的类型 | 三段颜色和画面里的终点、岔路、缺口一一对应 |

## 序 · 签名不说真话

- **概念**：TypeScript 的签名只写成功的类型。`divide(a, b): number` 不告诉你 b 为 0 时会 throw。Effect 把失败和依赖也写进类型：`Effect<number, Error, never>`。
- **意象**：同一根线，普通版本在中间裂开，值从图外掉下去，旁边写着“签名里没有这条路”；Effect 版本在同一个位置画出一条朱色岔路，左端是一个空的括号（R 是 never，什么都不需要）。
- **真实运行**：实验直接调用 `snippets/00-divide.ts` 的两个函数。`divideOrThrow(4, 0)` 抛出 `Cannot divide by zero`，`Effect.runSyncExit(divide(4, 0))` 返回 `Exit.fail(Error: Cannot divide by zero)`，画面上的两行字就是这两个结果。
- **文档**：[Why Effect?](https://effect.website/docs/v4/getting-started/why-effect)

## 一 · 程序是值

- **概念**：Effect 是惰性的、不可变的描述。创建它、给它 `pipe` 上 `map`，都不执行；`pipe` 返回新的值，原来的不变。只有在边缘调用 `runSync`，运行时才执行一遍，而且可以执行很多遍。
- **意象**：虚线图纸；上方留着“原来那张：没有变”的旧图纸；右边一个方框是 `count` 的读数。每颗珠子走完一遍，count 加一，终点旁写下这一次的结果。最后几张图纸装进一个数组：程序可以存起来、传出去。
- **真实运行**：实验每次从 `count = 0` 开始，创建程序后读一次 count（总是 0），再按旋钮调用 `runSync` 若干次，记下每次的结果和最后的 count。
- **文档**：[The Effect Type](https://effect.website/docs/v4/getting-started/the-effect-type)

## 二 · 一步一步写

- **概念**：`Effect.gen` 里用 `yield*` 取出一个 Effect 的结果，像 `await`。整段的错误类型是每一步错误的并集；第一处失败就短路，后面的步骤不执行。`Effect.fn("名字")` 给函数起名，名字变成追踪里的 span。行为（重试、超时、span）用 `pipe` 从外面套上。
- **意象**：线上三个站：`parse`、`findUser`、`return`。前两站下面各挂一条岔路。短路时，失败站之后的线变回虚线。上方的横杠是 span。最后三层虚线圈套在线外，各写一个 `.pipe(...)`。
- **真实运行**：实验直接运行 `snippets/02-gen.ts` 的 `greetUser`，并用 `Effect.withTracer` 装上一个记录型 Tracer。哪几站画成实线，看的是 Tracer 收到了哪些 span：输入 `"abc"` 只有 `greetUser` 和 `parse`；输入 `"7"` 多了一个失败的 `findUser`；输入 `"42"` 三个都成功。
- **文档**：[Using Generators](https://effect.website/docs/v4/getting-started/using-generators)、[Building Pipelines](https://effect.website/docs/v4/getting-started/building-pipelines)

## 三 · 两种错误

- **概念**：预期内的错误（failure）带标签，出现在类型的 E 里；`catchTag` 处理一种并把它从 E 里去掉，`catch` 处理剩下所有的，E 变成 `never`。defect（`Effect.die`）不在 E 里，这些处理器接不住它。fail、die、interrupt 都保存在 `Cause` 里。
- **意象**：三条朱色岔路，末端是 `NotFound`、`Timeout`、`Unauthorized` 三个标签。每架一座桥，底部类型签名里就少一个名字。defect 是一道从站点直落下去的虚线裂缝，它穿过所有桥的下方。
- **真实运行**：实验直接运行 `snippets/03-errors.ts` 的 `fetchProfile`（不处理）、`asGuest`（接回 NotFound）、`never`（全部接回）。这三个函数的返回类型写在代码里，由 `tsc` 检查；测试再检查画面上的 E 和这三处标注逐字一致。“bug” 那一格无论接回多少，结果都是 `Exit.die(profile is undefined)`。
- **文档**：[Two Types of Errors](https://effect.website/docs/v4/error-management/two-error-types)、[Expected Errors](https://effect.website/docs/v4/error-management/expected-errors)

## 四 · 重试与时间

- **概念**：`Effect.retry({ schedule, times })` 在失败后按时间表重来。`Schedule.exponential("100 millis")` 让等待翻倍，`Schedule.spaced("200 millis")` 等距。`times` 是重试次数，不含第一次。`Effect.timeout` 到点切断，正在跑的那一次被中断。
- **意象**：横向的时间轴。每次请求是一段粗线（100 毫秒），失败处一个叉；两次之间一道弧线，上面写着等了多久；timeout 是一条竖直的红虚线，切断处一道斜杠。时间轴在记录短于 2 秒时是 0–2000 毫秒，否则是 0–4000 毫秒。
- **真实运行**：程序在 `TestClock` 上跑，每次拨 10 毫秒。默认设置（第 4 次成功、exponential、times 5、timeout 2 秒）记下的请求起点是 0、200、500、1000 毫秒，1100 毫秒成功，和 `snippets/04-retry.ts` 的程序跑出来的完全一样。
- **文档**：[Retrying](https://effect.website/docs/v4/error-management/retrying)、[Timing Out](https://effect.website/docs/v4/error-management/timing-out)、[Using Schedules](https://effect.website/docs/v4/scheduling/using-schedules)

## 五 · 纤程与并发

- **概念**：每个 Effect 运行在一根纤程上。`Effect.all` 默认顺序执行；`{ concurrency: n }` 最多 n 根同时跑；`"unbounded"` 不限。结构化并发：一根失败，其余还在跑的被中断。`Effect.race` 先到的赢，另一根被中断。
- **意象**：五根平行的细线，每根代表一个任务。灰色点线是排队的时间，粗线是在跑，青点是完成，叉是失败，斜杠加“中断”是被中断。竖虚线标出总用时。
- **真实运行**：五个任务的时长 200、100、210、110、150 毫秒取自官方文档的例子。测试证明：顺序 770 毫秒，两根并发 460 毫秒，不限 210 毫秒；同时在跑的最多是 1、2、5 根；任务 2 在 100 毫秒失败时，其余四根都在 100 毫秒被中断；`race` 中任务 2 赢，任务 1 在 100 毫秒被中断。
- **文档**：[Basic Concurrency](https://effect.website/docs/v4/concurrency/basic-concurrency)、[Fibers](https://effect.website/docs/v4/concurrency/fibers)

## 六 · 服务与 Layer

- **概念**：R 列出程序运行前需要的服务。`Context.Service` 定义一种服务：一个名字加一个接口。`Layer` 提供实现；一个 Layer 也可以依赖别的服务，用 `Layer.provide` 接上。所有缺口都填上，R 才是 `never`，程序才能运行。测试时换一个 Layer 就行，业务代码不变。
- **意象**：线上两个缺口，半圆是 `Weather`，方形是 `Notifier`。下面的料架上有四块料：`Weather.live`（中间还空着一个三角形的 `Http` 缺口）、`Weather.test`、`Notifier`、`Http`。三角先嵌进 `Weather.live`，然后料填进线上的缺口，线才接通。
- **真实运行**：实验运行 `snippets/06-layers.ts` 的 `remind`，用里面定义的 `Weather.live` 和 `Weather.test`。线上版调用一次演示用的 `Http.get("/weather")`（不联网），得到“晴天，不用带伞”；测试版不调用 Http，得到“下雨，记得带伞”。忘了提供 Http 时，类型检查不会通过；硬跑的话，运行时报 `Service not found: app/Http`。
- **文档**：[Services](https://effect.website/docs/v4/requirements-management/services)、[Layers](https://effect.website/docs/v4/requirements-management/layers)

## 七 · 资源与 Scope

- **概念**：`Effect.acquireRelease` 把获取和释放写在一起，释放动作登记在 Scope 里；`Effect.scoped` 结束时按登记的倒序释放。失败、被中断都照样释放；没获取到的资源不会去释放。
- **意象**：回家开门、开灯、开窗，离开时关窗、关灯、关门。每样东西一条线，`[` 是拿到，`]` 是还掉，三条线嵌套成括号。右边一摞盘子是 Scope 里登记的收尾，后放的先拿走。
- **真实运行**：每次开、关都要 80 毫秒，倒序在时间轴上看得见。测试证明四种情况的收尾顺序：正常、待着时出错、400 毫秒被打断都是窗、灯、门；窗打不开时只有灯、门。`snippets/07-scope.ts` 在测试时钟上运行，打印的顺序也是开门、开灯、开窗、关窗、关灯、关门。
- **文档**：[Resource Management](https://effect.website/docs/v4/resource-management/introduction)、[Scope](https://effect.website/docs/v4/resource-management/scope)

## 终 · 织成一匹布

- **竖线**是前七章的内核：值、步骤、错误、时间、纤程、依赖、资源。
- **横线**是官方 onboarding 里“Out of the box”列出的能力：类型化错误、重试与调度、结构化并发、资源安全、依赖注入、可观测性、流、Schema、配置，再加一根“同一个生态”。
- **结**打在这项能力建立在哪几根竖线上的地方。例如“重试与调度”打在值、错误、时间上；生态那一根穿过所有竖线。这是一种读法，不是官方的分类。
- **v4 改了什么**：`@effect/platform`、rpc、cluster 等并进 `effect`，平台、驱动、AI 提供方的适配包单独发布，所有包统一版本号；运行时重写，最小程序打包约 6.3 KB（min + gzip）；`Context.Tag` → `Context.Service`，`Effect.catchAll` → `Effect.catch`，`Effect.fork` → `Effect.forkChild`，`Either` → `Result`；rc.118 起 `effect/unstable/http` → `effect/http`，ai、cli、sql、rpc、workflow 同理。
- **下一步**是官方学习路径的五站：The Effect Type、Installation、Creating Effects、Two Types of Errors、Basic Concurrency。
